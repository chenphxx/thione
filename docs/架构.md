# 架构

## 项目结构

```text
main.py                     单实例入口与 Tk 主循环
app/
  theme.py                  浅色与深色配色及 ttk 控件样式
  settings.py               最近使用的工具页面偏好
  imaging.py                缩略图与图片占位图
  browser/                  查重与重命名共用的文件浏览和预览组件
  shell/
    main_window.py          主窗口 页面切换与跨线程消息队列
    sidebar.py              简洁工具导航
    page.py                 工具页面基类与共用标题栏
  tools/
    dedupe/                 图片查重与重复项整理
    rename/                 批量重命名
    translate/              划词翻译与翻译 Provider
assets/images/logo.ico      窗口与托盘图标
```

## 页面模型

三个工具继承 `ToolPage` 并由 `app/tools/__init__.py` 注册 页面生命周期和后台线程消息通道保持不变 工具页面只负责自身业务交互 外壳负责创建页面 导航和退出收尾

## 主题与视觉

界面提供浅色与深色两套主题 窗口背景与内容表面随主题切换 文字使用适合当前表面的明暗对比色 并共用蓝紫强调色 状态色仅用于成功 警告和危险提示 用户可通过侧栏底部按钮或 `Ctrl+T` 切换主题 选择保存在界面偏好中

`app/theme.py` 集中定义两套颜色令牌 字体和 ttk 样式 卡片 导航按钮 输入框 表格和进度条使用同一组样式 不通过 PIL 生成按钮背景

导航使用标准 ttk 按钮 当前页面以主题强调色标识 页面直接切换 交互反馈采用 ttk 状态映射 不使用逐帧配色或位移动画 切换主题时会刷新文件网格自绘颜色与文件预览 文件预览和缩略图的读取流程保持原有后台加载方式

# 架构

## 线程模型

tkinter 有线程亲和性 所有窗口只能在主线程创建和销毁 因此除主线程外 其余线程一律不碰 tkinter 对象 

| 线程          | 职责                                   |
| ----------- | ------------------------------------ |
| 主线程         | 唯一的 Tk 根窗口与 `mainloop` 所有窗口 定时器 主题操作 |
| pynput 监听线程 | 键盘事件 命中双击 Ctrl 后取剪贴板并调用翻译接口          |
| pystray 线程  | 托盘图标与右键菜单                            |
| 激活监听线程      | 监听第二个实例发来的激活请求                       |

pynput 与 pystray 两个线程只在划词翻译启动期间存在 停止翻译会一并结束它们 因此程序空闲时没有键盘钩子 也没有托盘图标 

跨线程有两处投递通道 都采用 队列 + `after` 轮询 的模式 

- `ShellWindow.post(action)` 外壳级 供激活监听线程使用 轮询间隔 200 毫秒 
- `TranslateService._post(action)` 翻译服务内部 供热键与托盘回调使用 轮询间隔 60 毫秒 

两者的约定相同 投递方只入队 由主线程的轮询取出并执行 

退出时外壳会先取消自己的轮询定时器 再销毁根窗口 页面若持有定时器 也在 `on_close()` 里自行取消 

## 资源管理器风格的浏览组件

图片查重与批量重命名的文件展示方式完全一致 都由 `app/browser/` 下的四个部件拼出来

| 模块                | 职责                                 |
| ----------------- | ---------------------------------- |
| `file_grid.py`    | 文件视图 支持列表与缩略图两种展示方式 支持选中 双击打开与右键菜单 |
| `preview_pane.py` | 右侧预览窗格 图片 文本 表格 以及未知类型的文本兜底        |
| `details_pane.py` | 底部详细信息窗格 名称 类型 大小 修改时间 与位置         |
| `view_bar.py`     | 展示方式与缩略图大小分档 以及右下角的两个窗格开关          |

展示方式分列表与缩略图两种 列表一行一项 图标在左 名称在右 缩略图按容器宽度自动换列

缩略图分小 中 大三档 (64 / 128 / 192 像素) 换档或换展示方式时直接用已缓存的 PIL 图重画 不回磁盘 只有容器宽度变化时才重新排版

工具条上的 `视图` 是一组分段按钮 列表 小 中 大 对应 Windows 资源管理器的 查看 菜单; 选中 小 中 大 即回到缩略图展示 因此列表展示下这一组仍然可点

命中测试先把控件坐标换算成画布坐标 画布滚动过之后点中的仍是看到的那一项

只有扩展名在可预览图片列表里的文件才会真的去读盘 其余类型直接给占位图 

读盘只针对当前视口内的那几行 (上下各多留两行) 滚动停下之后再补读 因此打开大文件夹时不会一次性读进来几千张图 已解码的缩略图按最近使用保留最多 240 张 超出后淘汰; 读图在后台线程完成 结果经队列交给主线程分批贴到画布上 

两个窗格的开关有两个入口 工具条右侧的 `预览` 按钮与状态栏右下角的两个图标按钮 两者状态始终同步

## 工具一览

### 图片查重 app/tools/dedupe

- 扫描文件夹 按扩展名筛选 并以文件视图浏览 可切换列表与缩略图 缩略图分小 中 大三档 
- 选中文件后在右侧预览窗格看内容 在底部详细信息窗格看属性 
- 用感知哈希 (Python 差值哈希) 查重 汉明距离阈值见 `constants.HASH_THRESHOLD` 
- 查重在后台线程中进行 进度经队列回到主线程 
- 结果在独立的 `DuplicateGroupWindow` 中逐组勾选 可删除或整理到 `重复项` 子文件夹 

### 批量重命名 app/tools/rename

- 每张文件夹卡片独立选择路径 筛选与浏览 卡片内部同样是文件视图 并撑满页面剩余高度 页面右上角的 `刷新扫描` 重新读取各文件夹里的文件并同步列表与计数 
- 按 前缀 + 起始序号 生成新名字 
- 保存位置选原文件夹即原地重命名 内部先把冲突文件挪到临时名再统一改名 中途失败可回滚 
- 文件操作集中在 `renamer.py` 的 `run_tasks()` 里 页面只负责收集参数 展示进度与处理冲突 
- 预览与详细信息窗格挂在页面右侧与底部 所有卡片共用 
- 可预览的类型包括图片 文本 CSV 与 Excel (Excel 需要 `openpyxl`) 

### 划词翻译 app/tools/translate

- 可选三个翻译服务: 华为云 NLP uapipro 免费接口 60s API 在线翻译 页面上用单选按钮切换 选择保存在 `config.ini` 的 `[translate]` 段 
- 页面可分别选择源语言与目标语言 源语言默认自动识别 目标语言默认自动 也就是中文译成英文 其它语言译成中文 两项都选中文时按译成英文处理 两项选择也保存在 `[translate]` 段 与翻译服务一起生效 
- 不同服务支持的语言并不相同 选项由注册表给出 换服务时不受支持的选择回落到默认值 源语言只有一项时下拉框置灰 
- 华为云 NLP 需要 AK / SK / Project ID 单次最多 2000 字符 
- uapipro 免费接口不需要凭据 单次最多 3000 字符 源语言由服务端识别 通过 uapi SDK 调用 SDK 在第一次翻译时才导入 未安装只影响这一条路径 
- 60s API 在线翻译不需要凭据 数据来自有道翻译 源语言与目标语言都可以指定 用 httpx 直接调用 HTTP 接口 因此不引入额外的 SDK 依赖 
- 运行中换服务 换凭据或换语言立即生效 热键下一次触发就用新的设置 不必先停止翻译 
- 页面上的 `测试连接` 按当前选中的服务调用一次真实翻译 
- 默认不启动 打开 thione 时只装载已保存的选择与凭据 不建立热键 也不显示托盘图标 
- 页面上的 `启动翻译` 与 `停止翻译` 按钮控制开关 启动后才挂上全局键盘钩子 
- 选中文本后连续按两次 `Ctrl` 触发翻译 按住不放或两次之间夹了别的按键都不算 目标语言默认是自动 中文 (含自动识别出的中文) 译成英文 其余语言译成中文 
- 热键只统计用户真实按下的 `Ctrl` 自己合成的 `Ctrl+C` 由注入标记与执行窗口识别并忽略 按住期间系统补发的自动重复不算新的按下 一次按住超过 `CTRL_HOLD_LIMIT` (0.5 秒) 的算长按 既不计入双击 也不会留下影响后续双击的状态 
- 托盘菜单提供 打开主窗口 暂停热键 退出 
- 运行状态同时显示在页面状态行与外壳状态栏右下角 状态行里能直接看到当前的服务与翻译方向 
- 页面同时显示最近一次翻译结果 结果区固定在页面底部 长文本按卡片宽度换行 窗口高度不足时表单自己滚动 

#### 翻译服务的 Provider 架构

翻译相关代码分成两层: 业务层 (`page.py` `service.py` `hotkey.py`) 只认统一接口与服务元数据 各服务自己的差异全部留在 `providers/` 内 

- `providers/provider.py` 定义统一接口 `TranslationProvider.translate(text, source_lang, target_lang)` 统一异常 `TranslationError` 以及注册表 `PROVIDER_SPECS` 
- 注册表为每家服务记录显示名 说明文案 是否需要凭据 单次长度上限 语言代码表与构造方式 界面展示与配置校验都从这里取 业务层因此不出现 `if provider == ...` 这类判断 
- `providers/huawei.py` `providers/uapi.py` `providers/sixty.py` 分别封装一家服务 各自负责接口地址 请求方式 参数转换 认证 响应解析与异常转换 
- 构造方式在真正用到时才导入对应模块 没被选中的服务不会被加载 华为云 SDK 与 uapi SDK 都只在选中该服务后才进场 
- 语言代码分两层: 业务层统一使用领域语言代码 (`zh` `zh-Hant` `en` 等) 各服务自己的取值 (华为云 `zh-tw` 60s API `zh-CHT` uapipro `zh-TW`) 由 Provider 内部转换 不支持的语言在发起请求前就转成 `TranslationError` 
- 新增一家服务只需在 `providers/` 下加一个实现模块 并在 `PROVIDER_SPECS` 里补一条记录 页面 热键与配置读写都不需要改动 

## 与三个独立项目的关系

集成时做的关键改造 

- 三个项目原本都使用顶层包名 `app` 集成后按工具划分命名空间 分别是 `app.tools.dedupe` `app.tools.rename` `app.tools.translate` 
- 各自的 `main_window` 去掉了窗口创建与 `mainloop` 改为 `ToolPage` 子类 
- 划词翻译的后台服务不再自己创建隐藏根窗口 改为借用外壳的根窗口做轮询 
- 划词翻译由 启动即生效 改为默认不启动 需要用户在页面里显式开启 
- 用户配置目录由 `%APPDATA%\transpy` 统一到 `%APPDATA%\thione` 项目更名为 thione 后更名前使用的 `%APPDATA%\thpy` 与独立版旧的 `%APPDATA%\transpy` 都仍作为兼容来源读取 

独立版本已移出仓库 后续功能改动一律以集成版本为准
