# 架构

## 总体结构

thione 把三个原本各自独立的工具集成到同一个窗口里 代码分为三层 

- 外壳层 `app/shell/` 负责主窗口 侧栏导航 状态栏 主题与页面生命周期 侧栏宽度可由拖动手柄调整 它不认识任何具体业务 
- 工具层 `app/tools/` 每个工具一个子包 只实现自己的业务 对外暴露一个 `ToolPage` 子类 
- 共享层 `app/` 根下的模块 提供主题 日志 路径 界面设置 错误提示 图片缩略图 滚轮绑定与 Windows 平台调用 
- 组件层 `app/browser/` 提供资源管理器风格的浏览部件 图片查重与批量重命名共用 它只认文件路径 不认识两个工具的业务 

```
main.py                     入口 单实例 日志 根窗口
app/
  constants.py              外壳级常量
  paths.py                  用户配置 日志 资源路径
  palettes.py               默认主题的配色令牌与明暗推导
  theme.py                  主题管理器 样式表 字体与颜色过渡 全应用共用
  motion.py                 补间动画工具
  settings.py               界面偏好 (主题 上次停留的页面)
  logging_setup.py          日志与未捕获异常
  errors.py                 面向用户的提示与错误
  imaging.py                缩略图与占位图
  widgets.py                滚轮绑定等控件级工具
  win32.py                  单实例 任务栏分组 激活已有实例 打开文件与目录
  browser/                  资源管理器风格的浏览组件
    file_grid.py            文件视图 (列表与缩略图)
    preview_pane.py         右侧预览窗格
    details_pane.py         底部详细信息窗格
    view_bar.py             大小分档与窗格开关
  shell/
    main_window.py          主窗口 装载与切换页面 投递队列
    sidebar.py              左侧导航
    page.py                 页面基类 ToolPage
  tools/
    dedupe/                 图片查重
    rename/                 批量重命名
    translate/              划词翻译
assets/images/logo.ico      托盘与窗口图标
```

## 页面模型

三个工具都是 `ToolPage` 的子类 通过类属性声明自己在侧栏里的样子 

| 属性 | 作用 |
| --- | --- |
| `key` | 唯一标识 同时用于记住上次停留的页面 |
| `title` | 侧栏显示名 |
| `icon` | 侧栏图标字符 |
| `subtitle` | 切换过来时显示在状态栏的说明 |

生命周期回调 

- `on_show()` 页面切到前台 每次显示都会调用 
- `on_hide()` 页面切到后台 
- `on_theme_changed()` 主题切换之后调用 只有把颜色写进了数据而不只是控件选项的页面才需要实现 
- `on_close()` 主窗口关闭前调用 返回 `False` 可以阻止退出 

页面在启动时一次性全部创建 但只有当前页面会被放进内容区 因此切换页面没有创建开销 各页面也能在构造时准备好自己的状态 

`ToolPage` 另有两个便捷属性 `root` 返回外壳的根窗口 只用于 `after` 这类定时器 `window` 返回承载页面的顶层窗口 适合作为对话框的 `parent` 

页面的顶部结构由基类提供 三个工具页面都用同一套骨架 

- `build_toolbar()` 建立工具条 返回 `(bar, head, actions)` 标题与一行说明放在 `head` 的左侧 本页的操作按钮放进 `actions` (已经右对齐) 筛选条件这类次要控件在 `bar` 里再 pack 一行 
- `add_divider()` 在工具条与内容区之间补一条 1 像素分隔线 
- 需要顶替列表的空状态时 在内容区放一个占位块 给出引导文案与下一步动作 不留白屏 参见图片查重页的 `_update_empty_state()` 

## 主题与视觉

整体视觉按 ui-ux-pro-max 的 Flat Design 设计系统落地 只用 1 像素描边与留白分层 不画渐变与阴影 主色是蓝色 语义色与进度条用琥珀色 同一套配色在深色下整体反转为深蓝底 

配色令牌放在 `palettes.py` 只保留一套默认预设的浅色与深色两组基础令牌 界面用到的其它令牌 (悬停 输入框 滚动条 缩略图占位色) 由 `build_palette()` 按明暗方向往描边色方向推导 既保证两侧都朝正确的明暗方向走 又让派生底色带上和描边一致的冷色 新增令牌时不需要为两种模式各写一遍 

`theme.py` 里的 `ThemeManager` 由外壳持有 全应用只有一个实例 它做四件事 

1. 把令牌翻译成 ttk 样式 按钮 输入框 列表 卡片统一为扁平风格 描边 1 像素 
2. 通过 option database 为之后创建的 tk 原生控件提供默认颜色 
3. 递归遍历已登记的窗口 刷新 Canvas / Label / Menu / Frame 这些原生控件 
4. 维护当前的深色 浅色模式 切换时按帧插值做颜色过渡 

字体由 `sans()` 与 `mono()` 统一提供 前者用于界面文字 后者用于路径与序号 字体族在第一次创建根窗口时从系统已装字体里挑选 (优先 Plus Jakarta Sans 与 Inter 缺失时回落到系统界面字体) 中文字形交给系统的字体链接回退 

### 颜色过渡

切换模式时 `ThemeManager` 用 `motion.Tween` 在 180 毫秒内把当前调色板插值到目标调色板 每帧重新配置样式并刷新已登记的窗口 过渡只在结束时通知一次监听者 因此重建缩略图这类昂贵动作不会每帧触发 

需要跟着过渡一起变色的自绘控件 例如侧栏导航 用 `add_frame_listener()` 注册逐帧回调 只需要在切换结束后刷新数据的页面仍然实现 `on_theme_changed()` 

### 自绘控件的表面色

`_walk()` 默认把原生控件的底色刷成页面底色 `bg` 画在侧栏或卡片上的 Canvas 需要用 `_thione_surface` 属性声明自己的表面层 (`panel` 或 `card`) 否则切换主题后底色会对不上 

### 动效

`motion.py` 提供可取消的补间 `Tween` 补间挂在控件的 `after` 上 控件销毁后定时器随之消失 目前有三处动效 

- 深色 浅色切换时的颜色过渡 180 毫秒 
- 侧栏导航的选中指示条滑动 160 毫秒 与悬停底色淡入 110 毫秒 
- 页面切换时内容轻微上移到位 140 毫秒 

四处的时长都控制在 200 毫秒以内 符合扁平风格对轻量过渡的要求 也避免在低性能机器上拖慢操作 

切换入口有两个 `Ctrl+T` 与侧栏底部的按钮 结果写入 `settings.ini` 下次启动沿用 

工具页面不要自己创建 `ThemeManager` 也不要自己处理切换 需要在切换后重建的缓存颜色 在 `on_theme_changed()` 里刷新 

## 线程模型

tkinter 有线程亲和性 所有窗口只能在主线程创建和销毁 因此除主线程外 其余线程一律不碰 tkinter 对象 

| 线程 | 职责 |
| --- | --- |
| 主线程 | 唯一的 Tk 根窗口与 `mainloop` 所有窗口 定时器 主题操作 |
| pynput 监听线程 | 键盘事件 命中双击 Ctrl 后取剪贴板并调用翻译接口 |
| pystray 线程 | 托盘图标与右键菜单 |
| 激活监听线程 | 监听第二个实例发来的激活请求 |

pynput 与 pystray 两个线程只在划词翻译启动期间存在 停止翻译会一并结束它们 因此程序空闲时没有键盘钩子 也没有托盘图标 

跨线程有两处投递通道 都采用 队列 + `after` 轮询 的模式 

- `ShellWindow.post(action)` 外壳级 供激活监听线程使用 轮询间隔 200 毫秒 
- `TranslateService._post(action)` 翻译服务内部 供热键与托盘回调使用 轮询间隔 60 毫秒 

两者的约定相同 投递方只入队 由主线程的轮询取出并执行 

退出时外壳会先取消自己的轮询定时器 再销毁根窗口 页面若持有定时器 也在 `on_close()` 里自行取消 

## 资源管理器风格的浏览组件

图片查重与批量重命名的文件展示方式完全一致 都由 `app/browser/` 下的四个部件拼出来

| 模块 | 职责 |
| --- | --- |
| `file_grid.py` | 文件视图 支持列表与缩略图两种展示方式 支持选中 双击打开与右键菜单 |
| `preview_pane.py` | 右侧预览窗格 图片 文本 表格 以及未知类型的文本兜底 |
| `details_pane.py` | 底部详细信息窗格 名称 类型 大小 修改时间 与位置 |
| `view_bar.py` | 展示方式与缩略图大小分档 以及右下角的两个窗格开关 |

展示方式分列表与缩略图两种 列表一行一项 图标在左 名称在右 缩略图按容器宽度自动换列

缩略图分小 中 大三档 (64 / 128 / 192 像素) 换档或换展示方式时直接用已缓存的 PIL 图重画 不回磁盘 只有容器宽度变化时才重新排版

工具条上的 `视图` 是一组分段按钮 列表 小 中 大 对应 Windows 资源管理器的 查看 菜单; 选中 小 中 大 即回到缩略图展示 因此列表展示下这一组仍然可点

命中测试先把控件坐标换算成画布坐标 画布滚动过之后点中的仍是看到的那一项

只有扩展名在可预览图片列表里的文件才会真的去读盘 其余类型直接给占位图; 读图在后台线程完成 结果经队列交给主线程分批贴到画布上

画布上几百个图元的文字与选中框颜色不随主题过渡逐帧刷新 否则会拖慢动画 因此由页面在 `on_theme_changed()` 里调用 `apply_palette()` 统一刷新

两个窗格的开关有两个入口 工具条右侧的 `预览` 按钮与状态栏右下角的两个图标按钮 两者状态始终同步

## 工具一览

### 图片查重 app/tools/dedupe

- 扫描文件夹 按扩展名筛选 并以文件视图浏览 可切换列表与缩略图 缩略图分小 中 大三档 
- 选中文件后在右侧预览窗格看内容 在底部详细信息窗格看属性 
- 用感知哈希 (ImageHash dHash) 查重 汉明距离阈值见 `constants.HASH_THRESHOLD` 
- 查重在后台线程中进行 进度经队列回到主线程 
- 结果在独立的 `DuplicateGroupWindow` 中逐组勾选 可删除或整理到 `重复项` 子文件夹 

### 批量重命名 app/tools/rename

- 每张文件夹卡片独立选择路径 筛选与浏览 卡片内部同样是文件视图 并撑满页面剩余高度 
- 按 前缀 + 起始序号 生成新名字 
- 保存位置选原文件夹即原地重命名 内部先把冲突文件挪到临时名再统一改名 中途失败可回滚 
- 文件操作集中在 `renamer.py` 的 `run_tasks()` 里 页面只负责收集参数 展示进度与处理冲突 
- 预览与详细信息窗格挂在页面右侧与底部 所有卡片共用 
- 可预览的类型包括图片 文本 CSV 与 Excel (Excel 需要 `openpyxl`) 

### 划词翻译 app/tools/translate

- 可选两个翻译服务: 华为云 NLP 与 uapipro 免费接口 页面上用单选按钮切换 选择保存在 `config.ini` 的 `[translate]` 段 
- 华为云 NLP 需要 AK / SK / Project ID 由 `translator.py` 封装 
- uapipro 免费接口不需要凭据 单次最多 3000 字符 由 `uapi_translator.py` 封装 SDK 在第一次翻译时才导入 未安装只影响这一条路径 
- 两个实现对外都是 `translate(text)` 由 `translator.build_translator()` 按配置里的服务名挑选 页面与热键都不关心实际用的是哪一个 
- 运行中换服务或换凭据立即生效 热键下一次触发就用新的实现 不必先停止翻译 
- 页面上的 `测试连接` 按当前选中的服务调用一次真实翻译 
- 默认不启动 打开 thione 时只装载已保存的选择与凭据 不建立热键 也不显示托盘图标 
- 页面上的 `启动翻译` 与 `停止翻译` 按钮控制开关 启动后才挂上全局键盘钩子 
- 选中文本后连续按两次 `Ctrl` 触发翻译 中文译英文 其它语言译中文 
- 托盘菜单提供 打开主窗口 暂停热键 退出 
- 运行状态同时显示在页面状态行与外壳状态栏右下角 
- 页面同时显示最近一次翻译结果 

## 与三个独立项目的关系

`dupy` `renamepy` `transpy` 是集成前的三个独立版本 每个都是可单独运行的完整程序 它们已移出本仓库 集成后的代码在根目录的 `app/` 下 

集成时做的关键改造 

- 三个项目原本都使用顶层包名 `app` 集成后按工具划分命名空间 分别是 `app.tools.dedupe` `app.tools.rename` `app.tools.translate` 
- 各自的 `main_window` 去掉了窗口创建与 `mainloop` 改为 `ToolPage` 子类 
- 主题模块只保留一份 即集成前 `dupy` 与 `renamepy` 共用的那一份 
- 划词翻译的后台服务不再自己创建隐藏根窗口 改为借用外壳的根窗口做轮询 
- 划词翻译由 启动即生效 改为默认不启动 需要用户在页面里显式开启 
- 用户配置目录由 `%APPDATA%\transpy` 统一到 `%APPDATA%\thione` 项目更名为 thione 后更名前使用的 `%APPDATA%\thpy` 与独立版旧的 `%APPDATA%\transpy` 都仍作为兼容来源读取 

独立版本已移出仓库 后续功能改动一律以集成版本为准
