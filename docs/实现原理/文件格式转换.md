# 文件格式转换

## 功能目标

把音频 视频容器与音乐平台的加密文件批量转换成另一种音频格式 输出支持 MP3 WAV FLAC M4A OGG OPUS WMA AIFF 八种 

## 实现原理

### 输入格式

- 可以直接解码的音频扩展名与视频容器的扩展名分别维护在 `constants.py` 的 `AUDIO_EXTENSIONS` 与 `VIDEO_EXTENSIONS` 里, 添加文件与扫描文件夹都用它们与加密容器合并后的 `INPUT_EXTENSIONS` 
- 视频容器只取其中的音频轨: ffmpeg 的参数里有 `-vn -sn -dn` 视频流 字幕流与数据流都不参与转换; 要写封面时改成明确的流映射 只取音频流与附加图片流 声道数超过编码器上限时由 ffmpeg 自动混音 例如 5.1 的 E-AC3 转 MP3 会下混成立体声 
- 音乐平台的加密容器由 `platforms/` 子包还原: 按扩展名选用实现 转换页面只调用 `prepare()` 因此新增平台不需要改动页面里的流程 
- 还原结果写在系统临时目录里 要么被直接移到输出位置 要么在转换结束后删掉; 视频容器与普通音频不产生临时文件 
- 扩展名像加密容器而内容不是时 (已经还原过或者只是改了名字) 按文件头识别真实格式 直接参与复制或者转换 

### 转换引擎

- 编解码全部交给外部的 ffmpeg 可执行文件 程序用子进程调用它 因此项目里不引入音频编解码库 
- 一次转换就是一条 ffmpeg 命令: 输入文件 目标音频编码器 码率 (有损格式) 与输出文件 视频流与字幕流不参与转换 元数据尽量保留 
- 曲目信息用 `-metadata` 写进输出文件 排在 `-map_metadata 0` 之后 因此容器里带出来的标题 艺术家与专辑优先于音频流自带的标签 
- 封面作为附加图片流写入: 有封面时改成 `-map 0:a -map 1:v -c:v copy -disposition:v attached_pic` 并且不能再传 `-vn` 否则封面会被一起丢掉; 只有 MP3 FLAC M4A WMA AIFF 支持附加图片 其余格式忽略封面只写标签 见 `constants.py` 的 `COVER_FORMATS` 
- AIFF 要额外传 `-write_id3v2 1` 不打开时 ffmpeg 只写入标题 艺术家与专辑会被丢掉 见 `constants.py` 的 `FORMAT_TAG_ARGS` 
- 进度取自 ffmpeg 的 `-progress` 输出: 先读总时长 再用已处理时长算出百分比 

### 音质选项

音质分 无损 最高音质 与 有损码率 三类 无损不传码率 有损用 128 / 192 / 256 / 320 kbps 四档 最高音质档排在码率档之前 用来自动拿到编码器能给出的最好结果 

- 容器有无损编码时 无损选项排在下拉框最前 编码器换成无损的: WAV 与 AIFF 用 PCM 16 bit FLAC 与 OGG 用 flac M4A 用 ALAC 
- WAV FLAC AIFF 只有无损一项 因为 PCM 与 flac 没有码率的概念 
- MP3 OPUS WMA 没有无损选项 这三种编码格式本身只有有损模式 ffmpeg 也没有 WMA Lossless 编码器 这三种格式的说明文字改为一句话提示 需无损请选 FLAC 
- 最高音质档按编码器质量优先的那一档配置: MP3 用 320 kbps 并附 `-compression_level 0` OGG 用 `-q:a 10` 让 Vorbis 走质量模式 M4A 与 WMA 用 320 kbps OPUS 的编码复杂度默认已是最高 只把码率提到上限 
- opus 每声道上限 256 kbps vorbis 每声道上限 224 kbps 最高音质档里只有 opus 按 每声道上限 x 源文件声道数 换算码率 立体声因此是 512 kbps 单声道是 256 kbps vorbis 的 `-q:a 10` 是质量模式 不传码率 因此不会撞上 224 kbps 的每声道上限 手动选择的码率超过上限时按同一张表下调 否则单声道文件选 320 kbps 会被编码器拒绝 
- 音质下拉框后面有一行说明文字 解释当前格式的可选范围 可选项的差异因此能在界面上直接看到 

### 引擎定位

按下面的顺序找 ffmpeg 找到即用 

1. 用户在页面上手动指定的路径 
2. 系统 PATH 
3. 随程序附带的副本 由可选依赖 imageio-ffmpeg 提供 
4. 常见安装位置 winget 的 Links 目录 chocolatey scoop 以及 `C:\ffmpeg` 

- 都找不到时页面提示手动选择 ffmpeg.exe 仍然没有则不能开始转换 
- 随程序附带的副本在打包时由 PyInstaller 的 imageio-ffmpeg 钩子收集 见 `docs/开发与打包.md` 

### ncm 容器还原

- ncm 由文件头 元数据 封面 与音频数据组成: 文件头放着加密的音频密钥 音频数据用密钥派生的密钥流异或加密 
- 音频密钥的还原: 先按字节异或 `0x64` 再用固定的 AES-128 密钥做 ECB 解密 去掉 PKCS#7 填充与开头的 `neteasecloudmusic` 前缀 剩下的字节就是密钥 
- 音频数据用 RC4 的密钥调度算法生成 256 字节密钥流 从第二个字节起按周期循环异或; 异或按整数一次算完 因此 68 MB 的文件不到一秒 
- 元数据解密后取出标题 艺术家与专辑: 元数据区按字节异或 `0x63` 去掉 `163 key(Don't modify):` 前缀之后是 base64 与 AES-128 密文 解出来再去掉开头的 `music:` 前缀就是 JSON; 多歌手的取值用 `/` 连接 任何一步解不开都只当成没有标签 不影响转换 
- 封面按图片文件头判断是 jpg 还是 png 写进系统临时文件 与还原出来的音频一起交给页面 由页面在转换时写进输出文件 用完即删 
- 元数据与封面之后才是音频: 元数据之后先跳过校验码与填充 再按封面区长度跳过整块封面 
- 还原出来是 flac 还是 mp3 由音频数据的文件头决定 不依赖元数据里的格式字段 

### 批量流程

- 列表可以一次加入多个文件 也可以加入整个文件夹 加文件夹时递归收集扩展名在支持列表里的音频 已经在列表里的文件不会重复加入 
- 刷新扫描会重新读取加过文件夹的目录: 新出现的音频补进列表 已经不存在的文件从列表里移除 本次转换产生的输出文件不会再被扫描回来 
- 开始转换前把目标格式 码率与输出位置快照给后台线程 转换在后台线程里按顺序进行 线程只通过队列与主线程通信 
- 输出文件与已有文件重名时在文件名后追加序号 因此不会覆盖已有文件 
- 源文件已经是目标格式时只复制文件到输出位置 不重新编码 因此不会因为二次有损编码损失音质 复制用 `shutil.copy2` 完成 元数据与修改时间一并保留 
- 加密容器还原出来的音频本身就是目标格式时 带曲目信息或封面就改用一次流复制 (`-c:a copy`) 把标签与封面写进输出 音频流原样搬运 同样不做二次编码; 没有曲目信息时直接移动到输出位置 
- 同一编码格式的不同扩展名视为同一格式 例如 .oga 与 .ogg .aif 与 .aiff .m4b 与 .m4a 因此这些文件也只复制不再编码 
- 源文件已经是目标格式 并且输出位置就是源文件夹时直接跳过 既没有新文件也没有编码损失 
- 转换过程中可以终止 终止与关闭程序都会结束 ffmpeg 子进程 并删掉没有写完的输出文件 不会留下半成品 
- 输出位置的默认值是源文件夹 也可以指定另一个文件夹 
- 输出位置一行显示当前选择: 源文件夹时是一句说明 指定文件夹时是完整路径 点路径框可以重新选目录 
- 开始转换前确认指定的输出文件夹仍然存在 不存在时提示重新选择 而不是让每个文件都失败 

## 使用的依赖

| 依赖 | 用途 | 缺失时的表现 | 
| --- | --- | --- | 
| imageio-ffmpeg | 随程序附带 ffmpeg 可执行文件 | 可缺失 缺少时改用 PATH 或用户手动指定的 ffmpeg | 

加密容器的还原只用标准库实现 解密密钥块的 AES-128 见 `platforms/aes.py` 已经用 FIPS-197 标准向量校验过 因此没有引入加密库或者外部解密程序
