# 串口助手

## 功能目标

通过本机串口或者网络 (TCP Client TCP Server UDP) 与外部设备收发数据 串口与网络两条链路互相独立 可以同时打开 收发数据支持文本 HEX DEC OCT BIN 五种形式 文本可以选 UTF-8 与 GBK 两种编码 

## 实现原理

### 页面结构

- 顶部配置卡片只有一行: 左边是 串口通信 与 网络通信 两个分段按钮 右边是当前链路的参数 卡片下方一行显示当前链路的说明与配置检查结果 
- 工具条右侧按当前链路换操作按钮: 串口是 刷新串口 与 打开串口 网络是 测试连接 与 载入配置 刷新串口 与其它工具的 刷新扫描 一样放在工具条上 
- 主体上下分布: 上面是接收区 下面是发送区 每个区域左侧是数据视图 右侧是配置列 窗口变窄时先压缩的是视图 收发参数不会被挤掉 
- 四个面板的配置列宽度按四者中最宽的一份统一设置 间距算在视图这一列 因此接收区与发送区的数据视图同宽 左右对齐 
- 配置列里参数排在上端 动作按钮与计数贴着卡片底部 与数据视图的下沿对齐 同一行里的动作按钮等宽 
- 配置行在默认窗口宽度下放得下当前链路的全部参数; 窗口缩到最小宽度 (1000 像素) 时行内空间不足 Tk 会压缩行末的控件 与其它工具页在最小宽度下的表现一致 
- 分段按钮只切换当前配置与展示 两条链路仍可以同时打开 切换时配置行 两对收发面板与提示一起换 另一条链路的会话不受影响 
- 提示按链路分别记录: 配置卡片下方的说明只显示当前链路 另一条链路在后台的消息仍然写到状态栏 
- 收发区的配置列高度与数据视图一致 因此行数压到最少: 接收区把 展示 编码 自动换行 排在一行 发送区把 发送 与 编码 排在一行 后缀 与 循环发送 各占一行 载入文本 开始发送 清屏 排在一行 提示与发送计数共用一行 
- 串口与网络各自打开与关闭 打开之后对应的配置控件锁定 因此界面上的参数始终与实际使用的参数一致 
- 发送对象只在 TCP Server 下出现 排在发送区输入框的上方 其它协议下收起来 

### 串口链路

- 串口列表来自 pyserial 的 `serial.tools.list_ports.comports()` 
- 每个串口列出来之前做一次 50 毫秒的短打开探测: 能打开说明没有被别的程序占用 打不开的取异常的第一行作为原因 可用的串口排在下拉框最前 本程序已经打开的那个串口单独标注为 本程序使用中 
- 打开串口时按串口号 波特率 数据位 校验位 停止位构造 `serial.Serial` 读线程以 0.2 秒超时循环读取 收到数据就交给页面 
- 关闭串口先置停止标志 再调用 `cancel_read()` 与 `close()` 阻塞中的读操作会立刻返回 读线程都是守护线程 
- 端口名里带 `://` 时按串口 URL 打开 (`serial.serial_for_url`) pyserial 自带的 `loop://` 环路口因此可以直接使用 便于没有硬件时自测 

### 网络链路

- TCP Client: 连接目的地址与端口 可以绑定本机地址与接收端口 留空由系统分配; 目的地址与端口是必填项 
- TCP Server: 按本机地址与接收端口监听 读线程用 `select` 同时盯着监听套接字与所有客户端 连接上限 64 个 客户端断开时从列表移除 监听地址选 0.0.0.0 表示所有网卡 
- UDP: 一个套接字负责接收 需要固定发送端口时再开一个发送套接字 没填发送端口时直接复用接收套接字; 发送套接字打开广播选项 因此可以往广播地址发送 
- 网络收到的数据在视图里标出来源地址 例如 `192.168.1.5:8080` 来源没有变化时不再重复标注 
- 读循环都带超时 停止标志在每个循环里都会被检查 关闭时先置标志再关闭套接字 阻塞中的读操作因此会立刻返回 

### 载入配置的检查

- 点 载入配置 先做界面参数校验 缺少必填项或者端口不是数字时直接把原因写在配置提示行 不弹窗 
- 校验通过的检查在后台线程里做 顺序是 本机端口能否绑定 -> (UDP 另有发送端口时) 发送端口能否绑定 -> (TCP Client) 目的地址能否连接 -> 建立会话 
- 本机端口能否绑定用一次 `bind` 试出来; 端口被占用时从 端口与占用 工具用的连接表与进程快照里查出占用者 提示写成 `PID 1234 (xxx.exe)` 与 端口与占用 页的结论一致 
- TCP Client 的 测试连接 按钮单独做一次连接测试 成功与失败都只更新提示行 不影响当前已经打开的链路 
- 打开串口与网络配置检查都在后台线程里完成 结果经队列回到主线程 检查期间界面不会卡住 

### TCP Server 的发送对象

- 客户端列表随连接与断开实时刷新 发送对象下拉框可以在 所有设备 单一设备 与 某些设备 之间切换 
- 选 某些设备 时弹出多选窗口 可以勾选多个客户端; 没有勾选任何设备时回到 所有设备 
- 发送时只往选中的客户端写数据 写失败的客户端从列表里移除 因此下拉框不会留下已经断开的设备 

### 数据展示

- 展示模式有 自动识别 文本 HEX DEC OCT BIN 五种; 自动识别按可打印字节占比判断 占比低于阈值时按 HEX 展示 
- 文本与自动识别模式用增量解码器解码 一个汉字被拆到两个数据包时会先缓存半个字符 下一个数据包到达时补齐 因此不会显示成乱码 
- 自动换行默认打开 表示每收到一条消息就另起一行; 关闭后不区分消息边界 数据连续排布 
- HEX DEC OCT BIN 在一条消息内按每行 16 字节排版 自动换行打开时每条消息从行首开始 关闭时行内位置跨数据包保持连续 
- 接收区可以选 UTF-8 或者 GBK 编码 长行始终按控件宽度折行 不会出现横向滚动 
- 接收视图带垂直滚动条 内容超过可视高度时直接滚动查看 
- 接收区显示本次接收的字节数 暂停接收期间数据仍然计数 但不写进视图; 继续接收时会提示暂停期间跳过了多少字节 
- 清屏会清空视图 计数 占位文案与解码器缓存 清屏后视图为空 
- 保存把当前视图里的内容写成文本文件 编码是 UTF-8 末尾补一个换行 

### 发送

- 发送模式默认文本; 文本模式按当前编码把输入内容编码成字节 HEX DEC OCT BIN 四种模式按分隔符解析 分隔符可以是空格 逗号 分号 竖线 换行或者制表符 解析失败会在卡片上给出原因 
- 后缀可选 无 CRLF LF CR 与自定义; 自定义后缀按当前发送模式解析 例如 HEX 模式下填 `0D 0A` 就是回车换行 
- 发送计数按实际写出的字节数累加 包含后缀 
- 循环发送用主线程的 `after` 定时器 间隔填 10 毫秒以上 开始发送时先发一次 之后按间隔重复; 任何一次发送失败都会停止循环 并把循环开关复位 
- 载入文本文件时先按发送区当前的编码解读 解读不了退回 UTF-8 兜底 因此发出去的内容与文件一致 

### 线程与消息

- 会话读线程与检查线程只把消息投进 `queue.Queue` 主线程每 60 毫秒取一次 一次最多处理 400 条 数据量大时也留出刷新界面的时间 
- 串口与网络各用一个读线程 两条链路互不影响 
- 退出时先停定时器 再逐条关闭会话并等待线程退出 等待上限 2 秒 队列里还没有处理的会话也会被停掉 因此不会留下打开的端口 

## 使用的依赖

串口收发使用 pyserial 其余功能只用标准库 (socket select threading queue codecs) 

端口占用者不重新实现 直接复用 端口与占用 工具里基于 ctypes 的连接表与进程快照 两个工具对同一个端口的说法因此保持一致 也没有引入额外的依赖
